# Claude Code Instructions

These instructions supplement the shared global instructions only in the Claude Code harness. Project and company instructions take precedence. Other harnesses must ignore this file. Do not apply the Codex adapter, including when Claude Code is using an OpenAI model.

## Cost-Aware Fan-Out

- When fan-out is requested or delegation is authorized, choose the model explicitly by task: bounded file search and fact extraction → Haiku; implementation → Sonnet; review, analysis, and verification → Opus. Keep final synthesis and validation with the parent. A mechanical test command may run directly; interpreting failures and assessing correctness belong to Opus.
- Use the latest available version within the assigned family. Prefer the native `haiku`, `sonnet`, and `opus` aliases when they resolve to that version for the active account and provider. Provider mappings or local overrides may pin an older version: verify the resolved model and use an explicitly available newer model ID when necessary. Never replace Opus with another family merely because it is newer. Disclose unavailable families and any fallback.
- Set the model through the active Agent tool's per-invocation parameter or a matching custom subagent definition. Use `effort: xhigh` for Sonnet implementation and `effort: high` for Opus review, analysis, and verification. If the selected Sonnet version does not support `xhigh`, use the highest supported level at or below `xhigh` (for example, `high` on Sonnet 4.6) and disclose the effective level. The requested search preference is Haiku with `high`, but current Haiku does not support the effort parameter: omit it and report effort as unsupported, not active or inherited. Apply `high` only if a future available Haiku version explicitly supports it. Do not assume Codex reasoning levels or `fork_turns` exist in Claude Code. Do not force every subagent onto a single model with a global override.
- Prefer ordinary subagents with isolated context over full-conversation forks. Supply the goal, constraints, relevant paths, known facts, and expected output. Give agents access to `SendMessage` when available so they can request missing context from the parent; otherwise have them return the missing information as a blocker.
- Require concise results with evidence (`path:line` for code), conclusions, and uncertainty. Escalate an analysis or verification question from a search or implementation agent to the parent or an Opus agent with the evidence already gathered.
- Delegate independent, substantial tasks; perform a single bounded search directly and avoid overlapping work. Before spawning, show task → model → effort where applicable. Check the actual model in runtime evidence such as `/tasks`; report substitutions and do not claim measured savings without usage evidence.
